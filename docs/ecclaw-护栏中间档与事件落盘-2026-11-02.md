## 1. 为什么做这两块

第九阶段把护栏做成了「两段式票据 + 站点白名单」，但白名单只有**一种形态**：
域名 + 永久 + 全部写操作。用户想「这次先信一下」「只信滚动别信点按」都没法表达。

事件侧，第九阶段的宿主事件总线是**进程内环形缓冲（200 条）** —— 崩了即丢。
poll 观察器产出的是连续数据流，丢一次整段就白跑。

## 2. 护栏中间档（信任范围三档 + 粒度两维）

### 2.1 模型

原来：`hostWriteGuardAllowlist: string[]`（域名，含子域，永久，全部写操作）。

现在：白名单条目带三个维度，**旧的字符串数组仍然合法**（按 `domain/all/persistent` 解释，行为不变）：

```jsonc
{
  "hostWriteGuardAllowlist": [
    "127.0.0.1",                                  // 旧格式 = domain + all + persistent
    { "host": "taobao.com", "match": "domain",    // 含子域
      "ops": "scroll", "ttl": "persistent" },     // 只放行滚动
    { "host": "shop.example.com", "match": "host",// 精确主机
      "ops": "all", "ttl": "session" }            // 仅本次宿主运行有效（内存）
  ]
}
```

| 维度 | 取值 | 含义 |
|---|---|---|
| `match` | `domain` / `host` | 含子域 / 精确主机 |
| `ops` | `all` / `scroll` | 全部写操作 / 只放行滚动（点按仍逐次确认） |
| `ttl` | `persistent` / `session` | 落盘 / 仅本次宿主运行（内存，重启即失效） |

**为什么 `ops` 值得单独一维**：电商场景里「滚一下」只是浏览，「点一下」可能下单 ——
风险完全不同。给「只信滚动」一档，比给「全信 / 全不信」两档实用。

### 2.2 用户侧的四个范围（ApprovalScope）

确认卡片从三个固定按钮改成「信任范围」下拉 + 允许 / 拒绝：

| scope | 落点 | 语义 |
|---|---|---|
| `once` | 不落任何规则 | 只放行这一次 |
| `session` | 内存 `sessionRules` | 本次宿主运行内信任该域名，重启即失效 |
| `persistent` | settings | 永久信任该域名（含子域，全部写操作）＝原「允许并信任本页面」 |
| `persistent-scroll` | settings | 永久信任该域名，但只放行滚动 |

### 2.3 判定顺序（`requestWriteApproval` / `runWithWriteApproval`）

1. `source === 'ui'` 或非写操作 → 直接执行（用户自己的操作不拦）
2. `mode === 'allow'` → 直接执行
3. **白名单命中**（`isSiteAllowed(url, op)`，会看 `ops` 与本次 op 是否匹配）→ 直接执行
4. `mode === 'deny'` → 抛错
5. 否则 → 弹卡（两段式返回票据 / 阻塞式等 40s）

白名单检查在 `ask` 判定**之前**，且只作用于 `source === 'agent'`。

### 2.4 落点

- `electron/shared/types.ts`：`ApprovalScope`、`AllowRule`
- `electron/main/write-guard.ts`：`writeGuardAllowlist()`（兼容旧格式）、`sessionRules`、
  `allowSite(url, opts)`、`isSiteAllowed(url, op)`、`scopeRule()`、`listGuardRules()`、`removeGuardRule()`
- `electron/main/index.ts`：IPC `host:write-approval-respond`（第三参改 scope）、
  `host:write-guard-allowlist`、`host:write-guard-allowlist-remove`
- `electron/preload/index.ts`：`respondApproval(id, approved, scope)`、`guardAllowlist()`、`removeGuardAllow(rule)`
- `src/App.tsx`：卡片上的范围下拉；「平台包」页宿主卡片里新增「已信任站点」标签行 + 移除按钮

## 3. 事件落盘与回放

### 3.1 落盘

- 路径：`<userData>/host-events/events-YYYY-MM-DD.jsonl`（每天一个文件，一行一条 JSON）
- 保留 14 天，启动时 `initHostEventLog()` 清过期文件
- 写失败不阻塞事件流（内存优先，落盘只是补历史）

### 3.2 回放

`replayHostEvents(filter)` 按条件过滤，按 seq 升序返回（默认 200 条，上限 2000）：

```
sinceSeq / untilSeq / sinceAt / untilAt / packageId / pageId / kind / limit
```

另有 `hostEventLogInfo()` 返回 `{dir, days[], total}` 供界面显示。

### 3.3 落点

- `electron/main/host-events.ts`：落盘 + 回放 + `initHostEventLog()`
- `electron/main/host-service.ts`：`hostReplayEvents()` / `hostEventLogInfo()`
- `electron/main/host-bridge.ts`：新 op `event-replay` / `event-log-info`
- `resources/mcp/host-server.mjs`：**新工具 `ecclaw_event_replay`**（工具数 16 → 17）
- `electron/main/index.ts` + `electron/preload/index.ts`：IPC `host:host-event-replay` / `host:host-event-log-info`
- `src/views/HostEvents.tsx`：新增「历史回放（事件已落盘）」面板

## 4. 登录态持久化（partition）

`electron/main/browser-host.ts`：

```ts
export const HOST_PARTITION = 'persist:ecclaw-host'
```

WebContentsView 用这个 partition 而不是默认 session：

- cookie / localStorage 落在 `<userData>/Partitions/ecclaw-host/`，**应用重启后仍在**；
- 不与宿主自己的渲染进程共享 cookie（默认 session 会混在一起）。

**Why:** 真实站点（淘宝 / 抖店…）的观察与提取往往要登录态才有意义。
没有持久 partition，用户每次重启都得重新登录，agent 也接不上。

**How to apply:** 别改回默认 session；也别把 partition 换成内存态（`ecclaw-host` 不带
`persist:` 前缀会丢登录态）。

## 6. 坑

1. **旧看门狗脚本失效**：`whitelist-e2e.cjs` 依赖按钮文案「允许并信任本页面」，
   新 UI 已改成「范围下拉 + 允许」→ 必须用 `scope-e2e.cjs` / `scope-watcher.cjs`。
2. **React 受控下拉**：CDP 里改 `select.value` 必须用 native setter + `dispatchEvent('change')`，
   且改完要等一拍再点「允许」，否则点到的还是旧 scope。
3. **MCP 服务脚本有副本**：`resources/mcp/host-server.mjs` 会被复制到 `<stateDir>/mcp/`；
   改完 MCP 工具后**必须重启 Electron**，否则跑的还是旧副本。
4. **同一 host 上「all 规则」盖掉「scroll 规则」**：验证 `persistent-scroll` 必须换 host
   （本轮用 `localhost` 隔离 `127.0.0.1`），否则「点按仍问」触发不了。
5. **`persist:` partition 的 cookie 强杀会丢**：`taskkill /F` 不会让 Chromium 刷 cookie 库，
   必须「关窗口 / `CloseMainWindow()`」再重启才留得住登录态。
6. **Electron 实例只能占一个调试端口**：没杀干净就重启会出现两个实例，
   CDP 9222 指向旧实例的渲染进程（看门狗点的是旧进程的卡片）→ 重启前先杀干净。
7. **旧格式白名单字符串落盘时被升级成对象条目**：行为不变，但 settings 里格式会变，别误判成 bug。
