## 1. 达比是什么：一句话讲清它和 OpenClaw 的关系

达比常被误解成"给开源 AI 内核换了张皮"。**不是。** 更准确的说法是：

> **达比 = 开源 AI 内核（OpenClaw 原版，一行没改） + 一整套自研的桌面外壳 + 一整套电商站点能力包**

拆开看：

| 层 | 是什么 | 谁的 | 达比自己改了多少 |
|---|---|---|---|
| **内核** | AI 大脑：对话、推理、记忆、技能调度、工具调用 | **开源的 OpenClaw**，任何人可免费用 | 几乎没改。逆向扫描 110 MB 内核二进制，**一个电商业务词都没找到** |
| **外壳** | 用户看到的桌面软件：窗口、按钮、设置页、托盘、内嵌浏览器 | **达比自研**（Electron，主程序 4.6 MB，326 个内部接口） | 全部自研，这是达比的主要工作量 |
| **业务** | 淘宝、抖店、拼多多、京东…… 17 套站点工具包 | **达比自研** | 全部自研，这是达比真正的商业价值所在 |

**结论**：达比真正的产品力不在"AI"，而在**"让 AI 能安全地操作电商后台"**这件事上。
AI 能力是开源白送的；电商能力是达比自己一个包一个包攒出来的。

## 2. 达比的架构：用一个比喻讲明白

把 OpenClaw 内核比作**发动机**，达比自研部分就是**整车**：

```
┌──────────────────────────────────────────────────────────┐
│  桌面外壳（达比自研）                                      │
│                                                          │
│   ┌────────────┐ ┌────────────┐ ┌────────────┐          │
│   │ 聊天界面    │ │ 内嵌浏览器  │ │ 文件/邮件/ │          │
│   │            │ │ （侧边栏）  │ │ 预览/OCR   │          │
│   └─────┬──────┘ └─────┬──────┘ └─────┬──────┘          │
│         │              │              │                 │
│   ┌─────▼──────────────▼──────────────▼──────┐         │
│   │  电商站点工具包（17 套，按网址自动挂载）    │         │
│   │  淘宝 · 抖店 · 拼多多 · 京东 · 小红书 · …  │         │
│   └───────────────────┬────────────────────────┘         │
│                       │                                  │
│   ┌───────────────────▼────────────────────────┐         │
│   │  OpenClaw 内核（开源原版，一行没改）          │         │
│   │  对话 · 推理 · 技能 · 工具调用 · 记忆        │         │
│   └─────────────────────────────────────────────┘         │
└──────────────────────────────────────────────────────────┘
```

### 关键设计：AI 能"看见"网站，靠的是两个东西

1. **内嵌浏览器**：达比自己带一个 Chromium 浏览器，显示在聊天窗口旁边的侧边栏里。
   用户在上面正常登录店铺后台，AI 在同一个页面里工作 —— 所以 AI 天然带着用户的登录身份，
   不需要用户把账号密码交给 AI。
2. **站点工具包**：每个电商站点有一套工具（"查商品列表"、"改价格"、"导出订单"……），
   以插件包的形式独立发布。达比内置一个**注册表**，写明"什么网址该用哪套工具"。
   打开淘宝，就自动挂上淘宝那套；打开抖店，就换成抖店那套。

### 关键设计：知识不写死在代码里

每个站点工具包里还带着一份**站点说明书**（怎么翻页、按钮叫什么、报表在哪个菜单下）。
AI 读这份说明书 + 工具清单，就知道"在生意参谋后台怎么找昨天的成交数据"。
这比把每个后台的操作硬写进代码要好维护得多 —— 后台改版了，改说明书就行。

## 3. 达比在 OpenClaw 之上做出的创新

OpenClaw 提供的是"AI 会思考、会调工具"这件事。达比在它之上加了 **7 项自创**：

### 3.1 站点工具包体系（最有价值的一项）

- 每个包自带版本号、依赖、说明书，可以独立发布、独立更新。
- **按网址自动挂载**：打开 `databank.tmall.com` 优先用"天猫数据银行"的工具，而不是通用的淘宝工具。
  优先级是注册表说了算，不是代码说了算。
- 达比把它做成了**能上架的商店**：包从云端仓库下载、带哈希校验、安全解压、按渠道（稳定/测试）分版本。

> **我们照抄了什么**：完整复刻了包协议（清单文件 / 版本指针 / 注册表 / 运行时文件），
> 并且自建了一个等价的下载安装通道，还额外加了本地开发包目录覆盖，方便调试。

### 3.2 工具契约与敏感字段边界

达比给每个工具附一份"契约"，用统一的表格描述参数、用途，并且**显式声明哪些东西不能返回给 AI**
（例如店铺标识、Cookie、浏览器配置、隔离分区一律不许出现在工具返回值里）。
这是一条被产品化的安全边界，比"代码里注意别返回"要硬。

### 3.3 内嵌浏览器 + 侧边栏工作台

不是"AI 帮你截图"，而是**你和 AI 共用一个真实浏览器**：你看着它操作、可以随时接管。
同时保留书签、密码、历史、下载、私密浏览、跨设备同步 —— 这是达比体量最大的外壳资产。

### 3.4 社媒发布脚本 + "像人一样操作"的参数

抖音、快手、小红书、公众号的发布流程做成**声明式脚本**（像填表格），并且把"拟人化"做成了可调参数：
打字速度、误码率、额外停顿比例；再加一个**幂等窗口**（同一条内容 5 分钟内不重复发）。

### 3.5 内置业务包：淘宝商品上架

一整套上架流程单独打包，SKU 解析放到独立后台线程做，还带版本化的"工具契约 v2"。

### 3.6 会话分享 / 技能目录 / 技能分享

把一次对话打包成可发布、可撤销的链接；把技能做成目录供浏览、供分享。

### 3.7 多形态文件预览 + 画布 + 表格运行时

PDF、Word、PPT、Excel、PSD 都能在软件里直接预览；侧边栏里自带表格引擎和 OCR，
不用另外打开 Office。

## 4. 达比融合了哪些"别的软件"的能力

达比把一堆原本要单独开的软件**塞进了一个窗口**，这是它"桌面端"定位的实际含义：

| 融合进来的东西 | 在达比里扮演什么角色 | 像哪个现成软件 |
|---|---|---|
| **完整浏览器** | AI 的工作台；带书签/密码/历史/下载 | Chrome / Edge（竖向标签 + 侧边栏） |
| **邮件客户端** | 独立后台进程收发信 | Outlook / Foxmail |
| **办公文档预览器** | PDF / Word / PPT / Excel / PSD 直接看 | WPS / Office / Adobe |
| **OCR** | 侧边栏里识别图片文字 | 各家 OCR 工具 |
| **表格与数据分析** | 列式数据库 + Excel 扩展 + 自研数据库接口 | Excel / Tableau 的轻量版 |
| **社媒发布器** | 抖音/快手/小红书/公众号一键发文 | 各个平台的官方后台 + 群控工具 |
| **媒体与脚本运行时** | 内置图像处理、视频处理、Python、Node | Python 环境 / FFmpeg |
| **应用商店** | 站点工具包的下载、校验、灰度、回滚 | 手机应用商店 |
| **团队协作** | 成员体系、文件库、会话分享 | 飞书 / 企业微信（轻量版） |
| **遥测与崩溃上报** | 异常自动上报 | Sentry |
| **浏览器插件注入** | 往网页里插自己的助手脚本 | 油猴脚本 / Chrome 扩展 |

> **我们照抄了什么**：浏览器宿主、文档预览、OCR、表格、商店、协作 —— 这些是**通用能力**，
> 在 ecclaw 里属于"第二阶段候选"，还没做。
> 我们**优先**做的是"AI 能安全操作电商后台"这条主线，因为这是达比真正的差异化。

### 5.2 店铺登录态的分区管理

达比给**每个店铺**一套独立的浏览器身份（profile / 隔离分区），互不串号：
在 A 店登录了不会影响 B 店，Cookie 落盘、重启还在。这是电商多账号运营刚需。

### 5.3 私域数据资产

边界 CRM、企业 BI（`ecbis.cn`）、DMP 人群包 —— 这些是**商家自己的数据资产**，
达比把工具包直接接进去，让 AI 能查得到。

### 5.4 账号 / 计费 / 团队 / 遥测 / 数据迁移（私有商业系统）

一套完整的 SaaS 商业化外壳：手机号注册登录、套餐计费、成员与权限、远程能力开关、跨版本数据迁移。

> **我们刻意不做这一块。** 它是达比的收费模式，不是技术壁垒，做它只会消耗精力且无法验证。
> 这是本项目一条明确红线。

### 5.5 电商场景特有的"安全设计"

例如上架工具明确规定"只返回店铺公开摘要，不返回店铺标识/Cookie/配置/分区，
选店铺必须走另一个专门的确认步骤" —— 把"AI 不能自己乱选店"写进了产品契约。

## 6. 我们的逆向工程总体计划

### 6.1 方法论：换过一次方向，现在这条路是对的

| 阶段 | 做法 | 结果 |
|---|---|---|
| 最初 | 用自动化静态分析工具（REA）扫整个安装包 | **三次全失败**：整包 44 MB / 828 文件耗尽预算；定向到指定子目录仍被单个大文件拖到 300 s 超时；三次都是"退出码 0 但没产出证据文件" |
| 决定 | **改成"运行时产物直读 + 真机加载实测"** | 直接读已安装文件里的包协议、清单、注册表；再把 17 个真包**真的加载起来**，跑一遍看它们吐出什么能力 |
| 结果 | 反而更强 | 拿到了静态分析给不了的东西：包的真实匹配规则（藏在注册表不在清单里）、真实能力清单、真实的调用约定 |

**结论（已结案，别再重跑静态分析）**：对这种"运行时行为才是关键"的软件，
真机加载比静态反编译更可靠、更快、结论更硬。

### 6.2 总体策略：三条铁律

1. **不重造内核** —— 内核是开源的，直接用。精力全投在外壳和电商能力上。
2. **不改已定案的包协议** —— 照着达比的协议原样实现，保证**已装在用户电脑上的那 17 个真包能被我们直接驱动**。
   这是我们相对达比的天然优势：包是同一套，不用重新开发。
3. **不碰私有商业系统** —— 账号 / 计费 / 团队 / 遥测 / 迁移框架一律不做。

## 7. 已经完成了什么（按"能干什么"讲）

### 7.1 底座

- 软件能装能跑，AI 能真的对话（接的国内通义千问，实测一轮成功）。
- **大模型可以自己换** —— 任意兼容接口、任意自建网关、本地模型（Ollama / LM Studio / vLLM）都能接，
  这是相对达比最直接的增量：达比的模型是**白名单式**的，改不了。
- 设置、技能库、文件库都有界面可管。

### 7.2 电商能力（核心）

- 用户电脑上那 17 套达比真包，**我们能直接扫描、匹配、读出 643 项能力**。
- 每套包的能力清单会**自动写成 AI 能读的知识文档**塞进技能目录 —— AI 知道自己会什么、什么时候该用什么。
- 内嵌浏览器能真的开页面、读内容、抓网络响应、监听页面信号。
- **AI 已经能动手**：点击、滚动、拦截下一个网络请求、等待跳转 —— 可见页面走真实鼠标手势，隐藏页面走后台事件，两条路都验过。

### 7.3 安全（这是我们做得比达比还细的一块）

| 能力 | 说明 |
|---|---|
| 三档策略 | 每次问 / 全放行 / 全禁止（默认"每次问"，60 秒不响应自动拒绝） |
| 四档信任范围 | 只这一次 / 本次会话有效 / 永久信任 / 永久信任但只准滚动 |
| 白名单粒度 | 按域名或精确主机 × 按操作类型 × 按有效期，三维组合 |
| 两段式确认 | AI 先申请票据，人点"允许"才真的执行，超时作废 |
| 登录态持久化 | 店铺 Cookie 落盘，正常重启后还在（强制杀进程才会丢） |

### 7.4 可观测

- 所有宿主事件按天落盘成文本行文件，保留 14 天，单文件超 8 MB 自动开新分片，目录超 256 MB 从最老的一天整日淘汰。
- AI 可以**回放**历史事件、**汇总**事件（按站点包 / 按类型 / 按天三个维度），界面上也有面板直接看。

### 7.5 真机验证强度

所有阶段都是**在真机上跑断言**，不是"编译通过就算完"：

| 阶段 | 断言数 | 结果 |
|---|---|---|
| 第十阶段（四档范围 + 事件回放 + 登录态） | 15 / 12 | 全绿 |
| 第十一阶段（事件汇总 + 保留策略） | 22 | 全绿 |
| 累计已修的真实缺陷 | 15 个 | 见 `task.md` |

## 8. 下阶段要做什么

### 8.1 四个候选（来自上一阶段交接清单，按优先级）

| # | 事项 | 通俗解释 | 风险 / 依赖 |
|---|---|---|---|
| 1 | **真实站点登录态闭环** | 在用户自己登录的淘宝后台，完整走一遍"读数据 + 动手 + 护栏四档" | **需要用户本人的店铺账号**，写操作有真实业务风险，amazon 已知被反爬挑战页挡住 |
| 2 | **事件落盘后续** | ① 日志压缩归档（现在只有明文）② 趋势统计（环比 / 峰值，现在只有按天计数）③ **导出接口**（把某天的日志交给用户） | 无风险，纯本地 |
| 3 | **护栏后续** | ① 白名单支持"精确到路径"（现在只到域名/主机）② **"查看 / 清空本次会话的信任规则"入口**（现在设了但看不见） | 无风险，纯本地 |
| 4 | **事件主动推送** | 现在 AI 只能"我拉一下看有没有"，改成"有动静就推给 AI" | 改动最大，牵涉与 AI 内核的通道 |

### 8.2 本阶段（第十二阶段）建议落地范围

**主线（无风险、用户立刻能感知）**

1. **事件导出** —— 把选定时间段的事件导出成一份文件交给用户（AI 和界面都能触发）。
2. **信任规则看得见、管得住** —— 界面新增"本次会话的信任规则"列表，可查看、可一键清空；
   白名单支持精确到路径。
3. **事件趋势统计** —— 汇总视图增加环比 / 峰值，不再只有"每天几条"。
4. **日志压缩归档** —— 落盘从明文行文件升级为可归档格式。

**需要用户配合（单列，不阻塞主线）**

5. **真实站点登录态闭环** —— 请用户在自己已登录的淘宝/抖店后台跑一遍只读 + 一次低风险写操作，
   建议信任范围先选"本次会话"，别一上来就"永久"。
