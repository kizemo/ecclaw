# 逆向分析补充 — dabi 平台包协议与状态目录实证（2026-11-01 晚）

> 补 `docs/逆向分析-dabi-vs-openclaw.md` 第 7 节「未解事项」的前两项。
> 证据来源：**本机已安装的 dabi 3.0.18 的运行时产物**（比 REA 静态分析更硬的一手证据，
> 因为它是 dabi 自己写出来的数据）。路径：`%APPDATA%\com.dabiai.desktop\`。

## 0. 结论先行

1. **dabi 真实平台包目录 = `<pkgId>/current.json` + `<pkgId>/<dir>/{manifest.json,runtime.cjs,node_modules/}`**，
   `current.json` 的形状是 `{version, channel, dir}`。
   → **ecclaw 现有实现（读 `current.json.dir`）与真实数据完全一致**，无需改动。
2. **真实 `manifest.json` 里没有 `match` / `matchPriority`** —— 这两个字段在**注册表 `index.json`** 里。
   → **ecclaw 有个真实缺陷**：它只从 manifest 取匹配规则，装真实 dabi 包时会匹配不到站点。需修。
3. dabi 的 openclaw 状态根下确实躺着**内嵌浏览器 profile（sqlite + bookmarks + tabs）、mail/、file-library/**，
   证实「第二层外壳能力」与 openclaw 状态根同目录，ecclaw 的 `paths.ts` 目录语义对齐无误。

## 1. dabi 的 openclaw 状态根实测

`%APPDATA%\com.dabiai.desktop\openclaw\.openclaw\` 下实际存在：

```
browser-bookmarks.json          browser-tabs-v2.json(.prev)   browser-config-cache.json
browser-downloads.sqlite        browser-history.sqlite(-wal/-shm)  browser-passwords.sqlite(-wal/-shm)
browser-import-temp/             bookmark-html-import-temp/
file-library/files.sqlite       file-library/grants/

```

- 说明 dabi 把**内嵌浏览器的用户数据、邮件、文件库**都放在 openclaw 状态根之下，
  而不是放在 Electron 自己的 `userData` 根下 —— 与逆向报告 3.3 节「接缝」结论吻合。
- 本机 dabi **没有** `openclaw.json`（该机未登录/未跑过模型配置），故「openclaw.json 实际字段」一项仍未闭合；
  但该项已被**上游 openclaw schema** 覆盖（见 `handoff-ecclaw-phase1-2026-11-01.md` 第 3 节）。

同目录另有 `index.json.prev`（上一份索引）与 `retry-state.json`（安装重试状态）。

要点：
- `match[]` / `matchPriority` 是**注册表级**字段，不在 manifest 里。
- `packageUrl` 是 **OSS 签名直链**（`Expires` + `OSSAccessKeyId` + `Signature`），分母路径
  `/prod/skillManage/platform-packages/<pkgId>/<channel>/<uuid>/<pkgId>-<version>.xspkg`
  → 证实「远程包仓库 + 版本渠道（stable）+ 签名分发」。
- `.xspkg` 是包归档格式；本地落盘后展开成目录（见下）。

## 3. 包目录布局（真实）

```
platform-packages/
  index.json  index.json.prev  retry-state.json
  taobao/
    current.json                                  ← {version, channel, dir}
    stable-1.0.67-e4c2bf7b-1fb7-4ab8-9c9e-322f774793e5/
      manifest.json
      runtime.cjs
      node_modules/                               ← 包自带的运行时依赖
```

- 版本目录名格式：`<channel>-<version>-<uuid>`。
- `current.json.dir` 指向版本目录 —— **ecclaw 读的正是这个字段，实现正确**。

## 7. REA 侧状态（诚实记录）

- `C:/Temp/rea-dabi/evidence-app.json` **未生成**。三次尝试、三个不同原因，都已定位：
  1. **目标类型错**：`analyze-javascript_application` 只接受**目录或 `.asar`**，传单个 `main.js`
     报 `unsupported_target`（`retryable: false`，remediation 明确要求目录 / app bundle / .asar）。
  2. **`source_paths` 非精确路径**：报 `invalid_request` / `inspect_input_contract`，
     `source_paths[0]` 不是 inventory 里的精确文件路径（不允许 glob / 路径别名）。
  3. **整树跑不完**：即使指向解包目录 `C:/Temp/rea-dabi/app/`，也会在
     `dist/renderer/assets/client-BKeuIgQ2.js`（dabi 渲染层主 bundle）上耗尽整体预算，
     报 `Analysis operation timed out after 540000ms`；**exit 0 但不产出 evidence 文件**，
     且 `classDiagram-v2-*.js` 的语义分析「not started」。
  → **结论：整树分析对 dabi 这个体量不成立，必须 `--source-path` 定向到 dabi 自研目录。**
  可定向目标：`dist-electron/electron/browser/sidepanel-platform-runtime/`（5 文件 / 6.3 MB：
  exceljs / rolling-video / spreadsheet / **tesseract** / tesseract-worker）。
  其中 tesseract 说明 dabi 侧栏**内置 OCR**（对应逆向报告里 OCR 属于 dabi 第二层外壳能力）。
- 但本文件 1–6、9 节的证据是**运行时产物直读 + 真实加载**，强度高于 REA 静态分析，
  第 8 节四项未解事项已闭合两项半。
- REA 的 MCP 注册已移到 local scope（只挂 `E:/RE`），本项目内要用得走 CLI 回退：
  `npx -y rea-agents@6.8.0 analyze-javascript-application <目录或.asar> --source-path <相对路径> --detail summary --evidence_output <路径>`

## 9. `runtime.cjs` 加载契约实证（第二阶段补）

上一节第 5 节只从**静态字符串**里认能力 id。第二阶段做了**真实加载**，契约已闭合。

### 9.1 加载方式

`runtime.cjs` 是 **CommonJS 模块**，宿主用 `createRequire(runtimePath)` 加载，
且**在 require 之前必须注入** `globalThis[Symbol.for('com.dabiai.plugins.sdk')]`
（包内 `@dabi/plugins/index.cjs` 只做对这个全局量的取值与抛出）。
宿主从导出里找**同时含 `manifest` 与 `pages` 数组**的对象，再校验 packageId/version 一致。

### 9.2 平台包对象的两种形态

```
{ manifest, pages[], checkPageAccess, canOpenSidePanel, resolveSidePanelNavigation }   ← dabi
{ manifest, tools[], execute() }                                                        ← ecclaw 自带示例包
```

每个 page：

```
{ id, match(ctx), actions{capabilityId: fn}, automationActions{capabilityId: fn},
  observations(): [{id, ...}], observe(ctx), extract(ctx) }
```

- `automationActions` 是 `actions` 的子集（准备阶段）。
- `observations()` **依赖宿主传入的页面上下文**，脱离宿主调用会抛
  `Cannot read properties of undefined (reading 'url')` —— 探测时必须单独 try/catch。
- 另有第三种形态：`{ manifest, pages[], dataQueries{} }`（`databank` / `txsale`），
  `dataQueries` 的键是数据查询能力 id（如 `list-leaf-category`、`report-bidword`）。

### 9.4 动作执行依赖内嵌浏览器

dabi 宿主的调用链是
`sidePanelStrategyManager.actionHandler(context, capability, strategyId)` → `page.actions[capability]`，
而 `context` 携带 `webContents` / `tabId` —— 即 **dabi 的内嵌浏览器**。
ecclaw 尚无此宿主，故第二阶段只做到「能力目录抽取 + 呈现」，**不做动作执行**。

### 9.5 远程包仓库线索

dabi 主进程还有 `taobao-launch-packages` 处理器，负责
`runtime.cjs` + `sku-source-parser-worker.js` + `tool-contract.json`
（`hostApiVersion: 2`），含 manifest 哈希校验、zip 安全解包、OSS 签名直链下载与版本目录清理。
这是 dabi 远程包仓库的实现线索，ecclaw 尚未实现对应能力。
